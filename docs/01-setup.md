# 本地布局与协作边界

[返回目录](../README.md)

## 推荐位置

```text
D:/github_lianxh/
  teach-bank-guide/       工作手册的 Git 仓库
  dsed-book/              独立书稿仓库，示例路径

<你实际的坚果云同步目录>/
  teach-bank/             素材库
```

`D:/github_lianxh/teach-bank-guide/` 与你现有的 GitHub 项目存放习惯一致，作为本手册的推荐位置。`dsed-book` 是拟采用的书稿路径，不能据此认为该目录已经存在。坚果云根目录尚未确定，不能把示例路径当成配置。

三个目录分别回答三个问题：手册说明“怎样工作”，素材库保存“可以复用什么”，书稿决定“这本书最后怎样讲”。它们可以放在不同磁盘和目录中。

## Codex 中怎样安排

素材开发主要在 teach-bank 项目中开展，每个有明确产出的想法使用一个对话；另设一个维护对话处理目录、规则和公共索引。临时想法通常不需要再建一个项目。

写书时使用 dsed-book 项目，为各章开独立对话，并让该项目能够访问 teach-bank。手册需要持续修改时，可以另建 teach-bank-guide 项目。因此核心工作是两个项目，维护手册时可能出现第三个；无需先创建三个才能开始。

对话记录不能代替文件交接。每次阶段完成，把已接受结论、待定问题、来源、产物和下一步写入记录。多个对话避免同时修改公共索引、统一主题或同一份数据。

**操作约定：**书稿项目读取素材库；改进先形成回流提案，再更新素材源。这是工作纪律，不等于添加目录后就获得了技术上的只读保护。

产品界面和目录发现机制可能随版本变化。首次设置应核对当前客户端；项目功能见 [OpenAI 项目文档](https://learn.chatgpt.com/docs/projects)。本手册的目录约定不依赖某个固定按钮名称。

## 素材库拟议结构

```text
teach-bank/
  README.md
  AGENTS.md
  inbox/                  未整理想法和待处理资料
  library/
    textbooks/            教材结构与主题索引
    replications/         论文数据、代码与复现记录
    materials/            教学案例和可复用单元
    lectures/             旧讲义与章节资产
  projects/               选材单与书稿衔接记录
  exports/                交付给具体书稿的导出包
  _system/                规范、模板、类型登记和检查工具
```

你主要查看 inbox、选材单、预览和导出结果。元数据、关系索引和清单由 Codex 按模板维护，不要求你逐项手填。

新增第五个子库时，增加类型登记、目录、模板和必要检查，并复用共同的 ID、来源、状态、版本和关系字段。四个现有子库不需要重建。

## 第一轮试运行

1. 确认坚果云实际目录与手册仓库位置。
2. 创建最小素材库入口和规则，先登记一个案例。
3. 通过一次“教育组固定效应”案例完成入库与书稿导出。
4. 在另一台电脑重建并核查同一案例。
5. 工作流稳定后，再把常用步骤封装成 skills。

本轮只编写手册草案，不执行上述素材库初始化。
