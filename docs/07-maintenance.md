# 同步、版本与发布

[返回目录](../README.md)

## 坚果云与 Git 各自负责什么

坚果云方便跨电脑同步工作文件；Git 记录明确的修改历史。二者都不能替你安装运行环境，也不能保证多个设备同时修改同一文件时自动正确合并。

建议素材库先采用“一次一台设备写入”：旧电脑停止生成任务并完成上传，新电脑完成下载后再工作。并发冲突先保留双方版本，比较后合并，不能直接删除其中一份。可参考 [坚果云关于冲突文件的说明](https://help.jianguoyun.com/?p=1129)。

运行环境、缓存、浏览器配置和可重建搜索索引留在本机。不要把运行中的数据库或 `.git` 多设备并发同步作为默认方案；`.gitignore` 也不能替代坚果云的同步设置。

手册仓库放在 `D:/github_lianxh/teach-bank-guide`，通过 GitHub 在设备间同步。每台电脑独立 clone，工作前拉取，工作后提交和推送。素材库若以后也使用 Git，需要另定备份和工作副本安排，避免双重同步失控。

## 版本怎样记

文档记录有意义的修订，避免每句话一个版本。素材稳定 ID 不变，内容有变化时增加版本并写明影响；导出包记录它使用的各项版本。大型原始数据是否进入 Git，要结合体积、许可和获取方式决定。

Git 提交是文件历史，素材版本是可复用内容的标识，两者互相关联但不必完全相同。每个可发布批次登记提交号；暂不需要复杂的自动化发布系统。

## 从本地到 GitHub Pages

1. 审阅本稿，决定仓库名称、所属账号、可见性与许可证。
2. 使用本机已有 Git 凭据或连接的 GitHub 授权。尚未授权时，由你在可信登录界面完成登录。
3. 创建或选定远程仓库，检查本地待提交清单，设置 remote 并推送。
4. 配置 Pages 的发布来源，选择适合当前 Markdown 的构建方式。
5. 等待部署完成，逐页检查链接、中文、公式和移动端布局，再对外分享。

账号名称只用于定位，不能凭用户名自动登录。本次检测到连接账号 `lianxhcn`，但连接器授权、终端 Git 凭据和 Pages 管理权限可能不同，应分别验证。

[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) 将其定义为静态网站托管。推送成功并不代表网站部署成功；私有仓库和网站访问范围也不能简单画等号，发布前应实际核对。

本手册使用公开仓库 `lianxhcn/teach-bank-guide`，以 main 分支根目录为 Pages 发布源；已包含 Jekyll 配置和页面布局，无需自定义部署工作流。许可证尚待决定。

## 常见卡点怎样恢复

| 情况 | 下一步 |
|---|---|
| 新电脑能看到文件，代码却不能运行 | 按环境清单安装依赖，再运行最小验证 |
| 新对话忘了旧结论 | 读取入口、规则和阶段交接，不靠重述整段聊天 |
| 搜索没找到教材内容 | 核对索引范围、教材版本与处理进度 |
| 图形数值正常，网页白屏 | 检查脚本、资源路径和浏览器错误，视觉状态记为未通过 |
| 论文代码跑通但表格不同 | 核对样本、软件版本、随机过程和表格定义 |
| GitHub 已推送但网页没更新 | 检查发布来源、构建记录及部署状态 |

每次故障记录原因、修复和复验步骤。反复出现且步骤稳定的问题，再考虑做成脚本或 skill。
